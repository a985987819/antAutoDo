# Android 17 无障碍动作测试

## 方法

`test-actions.js` 在Auto.js自身前台打开自建原生测试弹窗，使用唯一测试按钮和长滚动列表，不操作支付宝、奖励、支付或系统设置。结果以按钮监听器、ScrollView实际偏移、弹窗dismiss事件验证，不仅看API返回值。测试弹窗关闭后停留Auto.js，需用户手动回到目标任务页。

## 当前设备结果

Android17 / API37，Auto.js Modify 4.1.24.0914.alpha：

- 首轮前台条件不成立，保护退出，无手势执行。
- 将Auto.js自身置于前台后，坐标`click(x,y)`返回true，但按钮未触发，**坐标点击未通过**，原因尚未定位，不能声称所有坐标手势都不可用。
- 重新定位测试按钮后，节点`click()`返回true，按钮监听器触发，**节点点击通过**。
- `swipe`返回true，测试列表实际scrollY增加，**滑动通过**。
- `back()`返回true，测试弹窗dismiss事件触发，**返回通过**。

这些结果仅覆盖自建原生弹窗，不代表支付宝Canvas/WebView节点同样可点，也不代表任务已自动化。禁止仅因API返回true就认定成功。节点点击仍需唯一定位、可信边界、前台检查、后置条件验证；无可用节点的图像按钮继续暂停，不以失效坐标盲点。

## 使用

用户解锁后，在Auto.js中运行`test-actions.js`，约数秒自动退出。控制台记录`ANTAUTODO_ACTIONS`。测试会将Auto.js自身切到前台，不修改系统设置。实际坐标取自本轮新建控件，不作为任务坐标配置。若失去测试前台或出现异常则清理自建弹窗退出。

后续：验证支付宝已明确授权的单个任务节点点击、返回和奖励状态；暂不批量运行，不自动兑换或抽奖。
