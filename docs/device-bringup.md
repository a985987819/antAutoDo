# 真机验证与当前边界

## 当前状态

Android 17 + Auto.js Modify已完成监督下的节点点击、press、swipe、back及部分任务操作；手机截图权限与1220×2656捕获已验证，稳定清晰画面与本地识别仍未验收，OCR未验证。当前Node核心主要用于离线测试，不声明其语法与异步接口兼容手机引擎。已有一次性探针和好友未验收原型，不存在完整业务的正式手机入口。详见[移动端能力审计](mobile-capabilities.md)。

## 已有能力

- `src/core/session.js`：默认干运行、动作预算、总时限、兑换预算及前台页面门禁。
- `src/core/runner.js`：串行执行、同一实例互斥、后置条件检查；真实执行要求适配器标记已验证。
- `src/tasks/manor/lottery.js`：纯状态规划，不会点击。原生模式未知、次数不足或抽尽模式会超抽时拒绝。
- `diagnose.js`：在候选运行器内手动运行，只检查接口存在，不截图、不点击、不读取界面文字，不请求权限。

接口存在不代表实际可用。`verified` 和 `liveValidated` 只是接口契约，不是安全沙箱；未来适配器必须通过识别和设备验证生成，不能在配置中随意设置来跳过验证。

## 手机连接后

1. 用户手动开启 USB 调试并授权电脑；电脑运行 `adb devices -l` 确认。
2. 选择官方来源、明确免费许可的候选运行器，先验证安装与基本脚本执行，不安装未知改包。
3. 将整个项目放到手机本地目录，手动执行 `diagnose.js`；报告仅在本地控制台显示。
4. 后续另行编写权限与截图探针，由用户确认正常权限弹窗；遇黑屏或受保护页面停止，不关闭系统安全保护。
5. 验证控件树可读性及离线中文 OCR。不得上传个人截图和界面文字。
6. 确认运行器模块/异步兼容性后实现适配器、有限时等待、可中断手势和暂停/急停入口。
7. 单任务 → 单 Tab → 双 Tab → 森林本人能量，逐级验收。

## 尚未实现

实际运行器适配、OCR、页面识别、坐标映射、截图权限、可中断动作、用户控制面板、打开/浏览动作、签到兑换、原生连抽、森林收能量。运行器 perform/observe 必须自带有限超时及取消能力；核心目前不会强制终止悬挂的适配器调用，不能开放真实执行。

## 本地验证

`npm test`、`npm run check`、`git diff --check`。无需安装依赖，不创建 lockfile。
