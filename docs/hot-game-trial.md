# 试玩庄园火爆小游戏：入口与环形计时观察

## 已实测

- 任务描述：打开即得30g饲料，玩一玩最多可得240g饲料，初始进度0/240。
- ADB控件树在实际已滚入画面时仍报告该任务及按钮零坐标，不能单靠此判断屏外。
- 经人工确认及实时原始截图验证可见后，Auto.js精确匹配完整任务文本，在仅两个孩子的任务容器内定位唯一“去完成”，节点click返回true；随后活动和画面实际进入游戏。零坐标节点的语义点击在此案例有效，不推广成允许盲点屏外节点。
- 实际打开的游戏为三国冰河时代。出现久未登录、分配新服务器提示，未点击确定，不自动处理账号/服务器选择。
- 奖励计时浮层位于左侧，并非固定右侧。局部截图黄色圆环长度发生变化。控件树提供任务浮层容器边界，但没有可读秒数或领取文字。
- 保底30g及额外饲料到账尚未确认；没有点击奖励、确认弹窗或返回。

## 后续识别方式

优先定位已验证任务浮层边界，在其中寻找饲料图标和黄色环形区域；对多帧圆环弧度、消失/重置、文字出现等变化分类。不能硬编码右侧或整机固定像素坐标。首版无需YOLO；普通局部图像分析足以作为候选方案，尚未实现自动分析代码。

变化只说明计时/动画发生，不证明准确剩余秒数，也不证明计时完成或到账。需要连续采样和状态去抖，排除加载动画、浮层移动、遮挡与循环重置。领奖只在明确免费奖励状态及唯一目标被验证时执行。返回后核对累计进度和实际领取状态，不用240g上限推断本轮必得。

## 入口诊断脚本

`probe-hot-game-entry.js`是一次性人工监督探针，仅匹配0/240及准确任务说明，仅点击一次节点，不重试、不领饲料、不执行其他游戏动作。它不是生产任务入口，也不能证明真实动作执行框架已接入。运行前需重新确认实际画面可见；游戏内容和名称可能变化，不默认允许所有随机游戏。

## 尚待验证

保底奖励到账时机、第一圈终态、循环是否自动发奖或需领取、每档时长与奖励、满仓提示、返回层级、运行器内截图与局部检测。未知弹窗不自动确认，不支付、不授权、不实际玩游戏、不看激励广告。截图仅留本地忽略目录，不提交控件树或个人采集数据。
