# 抽抽乐只读识别

## 已确认的能力

Android 17 + Auto.js Modify 4.1.24.0914.alpha 的现有诊断脚本可通过外部 Intent 运行并正常退出。接口探针确认无障碍服务、选择器、截图和申请截图接口存在；未发现全局 `ocr`，不代表所有本地 OCR 路径都不可用。实际截图尚未测试。

通过 ADB UIAutomator 只读观察，两个抽抽乐页面均暴露任务文字、进度、任务按钮和剩余机会文案。该结果尚未证明 Auto.js 选择器读取同样完整，需要后续探针。

## 规则

`src/tasks/manor/lottery-screen.js` 接受适配器规范化后的任务行，不接受任意平铺文字拼接。此前“每项都有独立行容器”的假设已被真机观察纠正：多个任务可能共享大父容器。后续提取器须结合标题、描述、限定兄弟序列及唯一可见按钮确定任务边界；有歧义则暂停，不能匹配大容器内第一个按钮，也不能只按最近坐标配对。现有识别函数尚未实现实际节点提取。

- Tab 文案和说明可能改变，不用于身份判定；统一标记 left/right。`tab-geometry.js` 对已验证容器中的两个同级可点击节点按水平位置排序，检查比例和重叠，不硬编码像素坐标。当前只定位目标，active始终未知；适配器必须独立验证当前页，才允许设置tabVerified。任务本身可被识别，但tab未知时不能交给抽奖执行规划。
- 基础任务识别函数仅覆盖每日签到、消耗饲料换机会、去杂货铺逛一逛三项。新增分类[按时长相关的游戏任务](lottery-timed-game-tasks.md)已记录独立规则，尚未接入自动执行。其他游戏进度任务、捐赠等不进入操作计划。
- 三个按钮均已完成且浏览进度3/3，才标记任务完成。
- 剩余次数必须有可见边界；零面积或屏外节点不作为可操作依据。
- 0次机会跳过；看不到次数则请求检查，不假定为0。
- 识别到一键连抽文字，不等于确认按钮、开关状态或连抽模式，当前始终未验证。

界面文案用于编写通用规则；不提交设备控件树、个人日志、截图或原始采集数据。测试全部使用人工构造的任务文字样本。
